## 1. 제안 배경 및 필요성

### 1.1 올림픽공원 테니스장의 환경적 특수성
* 서울 올림픽공원 테니스장은 1988 서울올림픽 유산으로, **총 19개 면(메인 1번, 실내 5~8번, 실외 2~4·9~19번)** 하드코트로 구성됩니다. 번호는 KSPO 공식 배치도를 따릅니다.
* 야외 테니스는 **풍향·풍속, 기온, 습도, 태양 위치**에 공의 체공과 바운스가 크게 달라지는 종목입니다.
* 이 구장은 국제 권장(남북 장축)과 달리 **장축이 거의 동서**입니다. OSM 센터코트 폴리곤과 위성에서 잰 장축은 **117°(ESE) / 반대 엔드 297°(WNW)** 입니다. 공공 API에 방위 필드는 없습니다.
* 같은 기상청 바람이어도 **서쪽 엔드와 동쪽 엔드의 맞바람·뒷바람·측풍이 반대**이고, 오전 서쪽 엔드는 서브 토스 눈부심이 큽니다. 실내 4면은 바람을 차단합니다. 메인 코트는 높은 스탠드 와류, 동측 실외는 도로변 노출이 추가 변수입니다.

### 1.2 이용자 페인포인트
* 현장에 도착하기 전에는 오늘 바람이 내 코트에서 맞바람인지 뒷바람인지 알기 어렵습니다. 기상 앱의 풍향은 북쪽 기준이라, 동서 장축 코트와 바로 대응되지 않습니다.
* 빈 코트 실시간 조회를 기대하지만, **코트별 실시간 예약 슬롯은 공공데이터로 열려 있지 않습니다.** 예약은 공식 온라인 예약 시스템에서만 가능합니다.

### 1.3 시설 운영(한국체육산업개발) 관점
* 개방된 이용 데이터는 **월별 일일입장·월회원 인원**입니다. 갱신 주기는 연 1회이며, 현재 공개분은 **2025년 12월까지**, 2026년 분은 2027년 갱신 예정입니다.
* 이 통계로 한산·혼잡 시즌을 보여 주고 공식 예약으로 넘기는 것은 가능합니다. **당일 빈 코트 알림·취소율 예측은 공개 데이터만으로는 구현하지 않습니다.**

## 3. 핵심 알고리즘 및 구현 내용

### 3.1 코트 축 정렬 풍향 벡터 분해
기상청 풍향 $\theta_{wind}$(0°=북풍)와 코트 장축 $\theta_{court}=117°$를 결합합니다. 서쪽 엔드는 117°를, 동쪽 엔드는 297°를 바라봅니다.

* 종방향: $V_{\parallel} = -V_{wind} \cdot \cos(\theta_{wind} - \theta_{heading})$  
  (+ 뒷바람·비거리 증가, − 맞바람·네트 위험)
* 횡방향: $V_{\perp} = V_{wind} \cdot \sin(\theta_{wind} - \theta_{heading})$  
  (측풍에 따른 좌우 휨)

실내 코트(5~8번)는 유효 바람을 0으로 둡니다.

### 3.2 볼 궤적·바운스·눈부심 (간이 모델)
* 체공시간(랠리 약 0.75s)과 항력 계수를 넣은 **추정**으로 비거리·좌우 편차를 cm 단위로 보여 줍니다. 유체역학 정밀 시뮬레이터가 아닙니다.
* 하드코트 바운스는 ITF 낙하 시험(2.54m)과 기온에 따른 공 내부 압력 변화를 반영한 COR 근사입니다. Fast / Medium / Slow 라벨은 이 근사값입니다.
* 서브 눈부심은 시간대별 태양 방위 간이 모델입니다. 동서 장축 때문에 **오전 서쪽 엔드**에서 위험이 커집니다.

### 3.3 코트 차이와 안내 규칙
실외 14면의 장축은 같습니다. 체감 차이는 방위각이 아니라 **실내 / 메인 스타디움 / 도로변 실외 / 서쪽·동쪽 엔드**에서 납니다.

* 강풍·초보: 실내 5~8번
* 메인 1번: 스탠드 차폐는 가정(×0.75). 측정값이 아님. 측면 와류 주의
* 9~17번 등 동측 실외: 도로변 노출
* 안내 문장은 규칙 기반입니다. Random Forest나 적합도 96.2점 같은 학습 지표는 사용하지 않습니다.

### 3.4 시설 이용 정보
* 15133891에서 해당 월의 일일입장·월회원·전년 동월 증감을 표시합니다. (예: 2025년 11월 일일입장 16,480명, 월회원 674명)
* 실시간 빈 코트가 아니므로 **공식 예약 사이트**로 연결합니다.

## 5. 기대효과 및 향후 과제

### 5.1 지금 가능한 효과
* 동호인이 **도착 전에** 오늘 바람이 내 엔드에서 맞바람인지 뒷바람인지 볼 수 있습니다.
* 주관기관 월별 이용 데이터와 공식 예약을 한 화면에 붙여, 공공데이터를 “조회”가 아니라 **현장 판단**에 씁니다.
* 동서 장축이라는 구장 특성을 숨기지 않고 안내합니다.

### 5.2 의도적으로 하지 않은 것
* 실시간 예약 슬롯, 예약 사이트 수집, 학습 모델로 포장한 추천, 가동률 개선 퍼센트 주장.

### 5.3 데이터가 열리면 이어서 할 일
* 코트별 예약·취소가 개방되면 한산 시간대·실내 전환 안내를 통계로 붙일 수 있습니다.
* 2026년 월별 이용은 2027년 갱신분에 맞춰 같은 API로 이어 받으면 됩니다.

### 5.4 실행과 시연
* 웹: `python -m streamlit run src/app.py`
* 모바일: `mobile/`에서 `npx expo start` (Expo Go)

**시연 순서 (약 1분, 웹 기준)**

1. 구역 **실내** → 5번, 유효 바람 0, 눈부심 없음.
2. 배치도에서 **1번 메인 / 5~8 실내 / 9~17 도로변**을 가리킨다. 장축은 같다.
3. 구역 **메인** → ×0.75는 스탠드 차폐 **가정**이라고 말한다.
4. 구역 **도로변** → 같은 실황에서 유효 바람이 메인보다 크다.
5. **서쪽 117° / 동쪽 297°**를 바꿔 맞바람·뒷바람이 반대임을 보여 준다.
6. 아래 **2025 월별 일일입장**과 **공식 예약** 버튼. 실시간 빈 코트가 아님을 한 줄로 말한다.
7. 폰에서 같은 코트 칩·구역 뱃지를 보여 준다.
